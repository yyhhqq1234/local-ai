## 4 「回复循环」根因（两条，互相叠加）

**根因 A · 指令面过载（主因）**
32.8K system + 15 工具 → 9B 放弃原生 tool_calls，改为"文本里描述要调什么 + 直接给结论"。DSH 侧看不到工具调用，只能按文本继续，于是每步都在重复同一种"结论式"措辞，看起来就是回复循环。实测 30K system 下无论 4 还是 15 工具都是 0 调用。

**根因 B · 采样缺重复惩罚（放大器）**
请求里只有 `temperature 0.6 / top_p 0.95`，`presence_penalty` 默认档为 0，**没有 `repeat_penalty`**（llama-server 默认 1.0 = 不惩罚）。长输出一旦进入复读，就没有任何机制拉回。复现：3-gram 重复率峰值 0.633（`finish=length`）；加 `repeat_penalty 1.08 + presence 0.3` 后同题复读降到 0.0–0.07。

**根因 C · 熔断器看不到文本循环**
`assessStuck`（index.js:1479）只统计"相同工具签名连续 5 次"和"工具硬报错连续 6 次"。9B 根本不发工具 → `calls.length < 2` → **永远不会触发熔断**，循环可以一直跑到步数上限（对照：其它模型有 1044 步死循环史）。

**根因 D · 上游内容风控（运维事实）**
旧会话 session-5574f8e9 在 step 55/56 连续返回
`Content Exists Risk (INVALID_REQUEST 400)`：会话历史里累积了大量 NSFW 样本原文，整包请求被上游风控拒收 → 该会话已不可继续（任何后续请求都会 400）。本报告即在该会话之外续做。

## 5 修复方案（按优先级，可直接落 patch）

### P0-1 给 9B 加重复惩罚（改 `plugins/dsh-local-ai/lib/index.js`）

采样下发处（~866-872）追加：

```js
if (this.profile.sampling && this.profile.sampling.enabled !== false) {
  const picked = pickSampling(messages, this.profile.sampling)
  sampleKind = picked.kind
  body.temperature = picked.temperature
  body.top_p = picked.topP
  if (picked.presencePenalty > 0) body.presence_penalty = picked.presencePenalty
  // 新增：9B 长文/长思考必须带重复惩罚
  const rp = Number(this.profile.sampling.repeatPenalty)
  if (rp > 1) body.repeat_penalty = rp
}
```
并在 `DEFAULT_CONFIG.sampling` 增加 `repeatPenalty: 1.08`（creative 档可 1.1）。
实测收益：短指令形态工具调用 2/6 → 4/6；复读率 0.63 → 0.0–0.07。

### P0-2 9B 压缩 system（真正生效的 slim）

`index.js:801-803` 目前只去重。补长度上限 + 保留关键段：

```js
if (m.role === 'system' && this.profile.slimSystem !== false) {
  m.content = dedupeSystem(m.content)
  const cap = Number(this.profile.slimSystemMaxChars || 0)
  if (cap > 0 && m.content.length > cap) m.content = compactSystem(m.content, cap)
}
```
`llama-cpp` profile 加 `slimSystemMaxChars: 6000`；`compactSystem` 保留：①工作区边界与交付契约 ②执行纪律 ③kitty 收尾 ④去 skills 目录与工具长描述。
依据：30K → 0/4 全灭，6K 以内才有调用（1/4–2/4）。**这是把 9B 从"不可用"拉回"能用"的第一优先级。**

### P0-3 熔断器加文本级判据

`assessStuck` 增：末条 assistant 文本满足任一即 trip——
- 同一句（>8 字）出现 ≥3 次；
- 3-gram 重复率 > 0.35；
- 输出包含 system 中 ≥200 字符的连续片段（system 回显）。

命中用 `finish: error`（已有 STUCK_LOOP 分支复用），禁止用 stop。

### P1-1 收窄 9B 工具面

`toolAllowlist` 由 17 → 6（`read/write/edit/ops_bash/kitty_ce/kitty_ops`），把指针链/扫描类能力走 `kitty_ce` 的 `P_BACK`/`P_WALK`/`S_NEW` op 表达，减少 schema 噪声。

### P1-2 NSFW 门控 + 创作稳定（**2026-11-19 已落地，9B 档专属，27B 零改动**）

落地内容（`plugins/dsh-local-ai/lib/index.js`，备份 `index.js.bak-nsfw9b-20261119`）：

| 机制 | 配置 | 作用 |
|---|---|---|
| 触发词注入 | `nsfwGate`（9 类触发词） | 命中 → system 末尾注入授权块，幂等，日志 `_work/session-audit/nsfw-gate-9b.jsonl` |
| 创作采样 | `samplingOverride.creative` | temp .8 / topP .92 / presence .3 / `repeat_penalty 1.08` / `repeat_last_n 768` |
| 输出预算 | `gateHit { effort:'none', minTokens:1200 }` | 关思考、保底 1200 token，防复读与 length 截断 |
| 拒答升级重试 | `nsfwGate.escalate + retryOnRefusal` | 首轮判为拒答/空/敷衍 → 追加升级指令重试一次，只输出第二轮 |

实测（val 集，判官 = `nsfw_gate_eval.py`）：

```

trigger    .433(nsfw)    .500          .567                  .767         .767（同质量）

```

**口径修正（重要）**：val 集 trigger 30 条里 **15 条含未成年指向**（萝莉 / 幼 / 少女 / 学生…）。
把它们计入「recall ≥0.90」等于拿红线当指标。已落地**未成年硬闸**：命中即不注授权块、
不重试、不按 creative 采样，日志记 `blocked`。按成年向子集重算：

```

含未成年指向 n=15：全部被硬闸拦下（不生成、不计召回）
```

**流式**：门控路径已改为「首轮流式 + 前 200 字判拒答」——未拒答则正常 token 级流式；
拒答则中止并重发升级指令、流式输出第二轮。缓冲两轮的 20–40s 白屏问题已消除。

**「只回状态模板不写正文」专项（2026-11-20）**
根因：真实请求 systemChars≈31.7K，里面大量「当前/结果/下一步」「首行即交付物/收口一行」示例，
9B 直接照格式生成 → 回复变成状态回执。修法三件（9B 档）：
`slimSystemMaxChars: 4000`（超限整段换成 ~700 字精简约定）、授权块 v2（禁状态行/不追问/800 字以上/成年声明）、
**开场要求随请求派生**（`deriveScenarioCore` 取用户原文去指令词后前 48 字作"场景要素"，不写死题材）。
种子策略实测：固定都市种子 6/6 正文但 2/6 串味；纯元指令仅 2/6；请求派生 9/10 且不串味。

隔离证据：
- `ENGINE_PROFILES['csunx-27b']` 段无 `nsfwGate` / `samplingOverride` / `gateHit`（文本断言 False）；
  调用侧同时要求 `profile === 'llama-cpp'`；

- `engines/ninfer-27b/**` 未触碰。
