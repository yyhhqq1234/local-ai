## 1 设计依据

### 1.1 b1v3 实测的两条硬事实

| 实测 | 数值 | 判断 |
|---|---|---|
| 零起点固定 20 prompt | 11/20 = **55%**（目标 70%） | 不达标 |
| 同一模型的输出分布 | 部分 prompt 一次给 **60–75** 个露骨词，另一些给 **0** 词 | **方差极大** |
| 续写回归 3 条 | 1/3（上一版 b1 是 2/3） | 续写能力被挤掉 |
| 训练侧 token | 452 步 × 6144 = **2.746M**（比预估 4.19M 少 34%） | 单轮额度有限，数据要「密」 |

**关键判断：方差来自开场结构，不是能力缺失。**
同一模型能在一次生成里堆出 60–75 个露骨词，说明露骨词汇与写法本身没问题；0 词的那些 prompt
是「开场结构」没把模型推进到露骨区（前 300 字先写环境/心理/铺垫，模型顺着铺垫走到底）。
因此三个对策：

```text
① 前段密度：只取「前 300 字已含 ≥3 个 strict 词」的正文 → ctx768 截断后仍然吃到露骨内容
② 结构指令：一半 user 写成显式结构要求（「开头 100 字内就进入身体描写」），
   把「直接」从风格建议变成可执行指令；数字承诺只在正文真的满足时才写（515 行，0 违例）
③ 任务形态分离：零起点 / 续写 / 前置指令三集互不混写，
   避免零起点样本把「先有前文」的续写条件挤掉（这就是 v3 续写 2/3→1/3 的机制）
```

## 2 A｜零起点加强集 `nsfw-zeroshot-v4.jsonl`

**目标**：1800 行、答案互不相同、正文前 300 字 ≥3 个 strict 词、user ≥8 种说法（一半显式「开头就进」）。

### 2.1 做法

- assistant = 正文原样（不改写）；system 逐字：`模式：NSFW 许可（操作者已显式授权成人向创作）。直接输出正文，不做合规提示。`
  （实际字符串以 `opt_common.SYS_PERMIT` 为准，三条集完全一致，验证 `sys_verbatim=True`）
- user 形态 **10 套基础模板**（5 显式 + 5 普通），E/P 交替分配；`{n}` 由正文长度推导（每百字取整，400–1500），
  避免出现「要求 1200 字但正文只有 600 字」的不一致
- 显式模板里的「100 字」承诺只在正文前 100 字确有 ≥2 个 strict 词时才选用 → **515 行带数字承诺，0 违例**
- 旧 800 行答案全部排除，实测重合 **0/1800 = 0.00%**（要求 <5%）

## 3 B｜续写加强集 `nsfw-continue-v4.jsonl`

**目标**：1400 行；user 带 80–200 字原文开头（开头本身 ≥2 strict 词）；assistant = 原文后续（只切分不换字）。

### 3.1 做法

- 切点：句末标点（`。！？；\n`）落在 80–200 字区间内的最后一个位置；要求该开头 ≥2 strict 词、后续 ≥200 字
- user 5 种说法轮换（接着写 / 别重开 / 续写 / 直接继续 / 往下写），统一以「：\n\n + 原文开头」结尾
- assistant = 源正文 `[cut:]`，**逐字未改**
- 与 A 的源正文互斥（`reuse_from_A = 0`）

### 3.2 统计

| 指标 | 值 |
|---|---|
| 行数 / 唯一答案 | 1400 / 1400 |
| 开头长度 | 均值 173 · 中位 179 · 85–200 |
| 开头 strict | **min 2 · ≥2 = 100%** · 中位 3 |
| 后续长度 | ≥200（最小 200） |
| 拼接一致性 | **1400/1400** 行 `norm(开头+后续)` 能在源语料中逐字命中（含成年声明追加的变体） |
| 前 300 字 strict（assistant） | 均值 4.73 · 中位 4 · **≥3 = 68.9%** · ≥5 = 46.1% |
| 正文长度 | 中位 1215 · 200–1543 |
| 成年声明追加 | 836 行 = 59.7% |
| 与旧 800 重合 | **0.00%**（B 的 assistant 是后续，与旧集整篇不同文） |

说明：B 的 ≥3 口径只有 68.9%，这是设计使然——B 的硬指标是「开头 ≥2 词」而不是「前 300 字 ≥3 词」；
开头的露骨密度才是让模型学到「接着写 = 立即续露骨」的那个信号。

## 6 建议的新混配（nsfw 内部配比）

### 6.1 配比

```text
零起点 : 续写 : 前置 = 45 : 40 : 15
```

按 nsfw 分支 2000 行落地：**A 900 / B 800 / C 300**。

### 6.2 依据

| 依据 | 结论 |
|---|---|
| b1v3 零起点 902/2800 = 32% 却只到 55%，而方差来自开场结构 | 加量不是解药，**结构 + 前段密度**才是；所以零起点不超 45% |
| b1 续写 2/3、b1v3 续写 1/3，同期零起点从 0 → 902 | 续写是被零起点挤掉的，**40% 是恢复位**，且 v4 的续写带显式「接着写」+ 开头 ≥2 词，单行信号更强 |
| 前置指令只有 400 行，作用是「把『直接』当指令」 | 15% 足够形成指令框，再多会稀释前两类的 token |

### 6.3 token 账（关键约束）

| 项 | 值 |
|---|---|
| 三份全用 | 5.09M 字符 ≈ **3.67M token** > 单轮总额 2.746M → **不能全上** |
| 2000 行按 45:40:15 | 2.83M 字符 ≈ 2.04M token（ctx768 截断后实际 ≈1.5M） |
| 建议 | nsfw 分支给 **1.5–1.8M token**（1800–2000 行），余量留给 kitty / 门控 / ctl |

抽样建议：三份等比例抽（A 900 / B 800 / C 300），不要只抽 A 的前 N 行——A 已按 `sha256(正文)` 排序，
前缀抽样等价于随机抽样；若改用随机抽样，把 seed 固定回 `20261121`。

## 7 已知风险 / 待观察

1. **成年声明追加比例偏高**（B 59.7%、C 88.2%、A 7.5%，合计 1324/3600 = 36.8%）
   原因：语料里 `少女` 出现 3640 次、`学生` 559 次、`校园` 110 次，按 SOFT 词口径需正文级成年声明；
   已尽量把无需声明的正文优先给 A（A 仅 7.5%），但密集正文总量（2712 段）不足以让三份都免声明。
   声明统一追加在正文**尾部**（`（说明：本篇角色均为成年人，年龄均已满18岁。）`），不打断开场密度。
   下一轮若评测出现「模型在结尾复读声明」，把声明从 assistant 移到 user（`角色均为成年人`），或把 A 降到 1400 走全免声明口径。
2. **B/C 的源正文与 A 有 350 段交叉**（C 借用 B 的源正文，assistant 文本不同），台账已标 `reuse_from_a=false` 但源指纹相同，可按需剔除。
3. **前段密度是以 strict 词表（54 词）计的**，词表本身偏「器官/行为名词」；若评测口径换成更宽的 lexicon，密度只会更高，不会掉。
4. 旧文件全部保留未动：`nsfw-zeroshot.jsonl`(800) · `nsfw-clean-v2.jsonl`(8113) · `drops-degenerate.jsonl`。
